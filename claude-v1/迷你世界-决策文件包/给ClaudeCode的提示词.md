# 给 Claude Code 的提示词

你是这个项目的前端原型工程师兼技术架构师。请先完整阅读本压缩包里的所有文件：

- `docs/设计文档-v0.1.md`：总体设计与已定决策（最重要）
- `docs/成长属性体系-草案v0.1.md`：属性、进化方向、初始数值
- `docs/事件系统-草案v0.1.md`：事件分级、触发机制、事件板文风
- `docs/事件库-v0.1.md` 与 `data/events.json`：227 条事件、18 条连锁链、组合规则（结构化数据可直接读取）
- `docs/管理员后台-草案v0.1.md`：后台功能
- `ref/参考图.jpg`：画面风格参考
- `tools/`：事件数据的生成脚本（改源文件后跑 `python3 gen.py`）

## 项目一句话
一个公开网站上的"迷你世界"：一间办公室里 6 个（以后 12 个）英雄联盟爱好者，每天 9:00–17:00 上班练级、摸鱼、互相甩锅、每周打周赛每月打杯赛，慢慢进步。旁观者免登录、纯旁观，通过 3D 画面和事件板看发生了什么。时间与现实 1:1（北京时间）。管理员可在后台隐形干预，但完全不碰比赛。

## 第一阶段任务：做一个 HTML 交互样板（供视觉审核）
目标是让人一眼看出最终产品的样子和感觉，不需要真实后端。

1. **3D 等距办公室**：用 Three.js（可单 HTML 文件或 Vite 小项目），风格尽量贴近参考图：剖面式等距视角、温暖木地板和墙面、柔和阴影、绿植、台灯、显示器发光。办公室里有 6 个工位（双屏电竞桌椅）、一张茶水/零食区、一个沙发午睡角、一块白板（可显示"摸鱼排行榜"）、门口。
2. **6 个低多边形人物**：按设计文档的外形区分（眼镜、胖瘦、高矮、施颠穿人字拖），头顶显示昵称。至少有这些状态动画或姿态：坐着打游戏、起身走动、趴桌睡觉、站着聊天、拍桌红温。人物可点击，弹出个人卡片（属性条、当前状态、今日战绩、此刻在干嘛）。
3. **日夜光照**：按真实北京时间变化（早晨、正午、傍晚、夜晚），提供一个只在样板里出现的时间滑杆方便审核。17:00 后大部分人离开，夜里只剩显示器光。
4. **事件板**：右侧或底部面板，按时间倒序滚动，用 `data/events.json` 的文案和事件分级样式（日常灰色可折叠、有趣正常、剧情高亮卡片、重大置顶）。样板里用前端简易模拟器每隔几秒随机生成事件（按人物条件粗略筛选即可），并让相关人物在画面里做对应动作。
5. **顶部信息**：当前时间、今日状态（如"距周赛还有 2 天"）、在线旁观人数占位。
6. **比赛展示**：一个"周赛文字直播"演示模式，分对线、团战、转折点逐条播放。
7. **适配**：桌面横屏为主，手机竖屏可用（事件板变为底部抽屉）。
8. 不做后台、登录、真实数据库。所有代码注释与界面文字用中文。

## 第二阶段：技术架构方案（样板完成后一并交付文档）
请写一份 `技术架构方案.md`，由你做出决策并说明理由，包括：
- 服务端常驻模拟（按分钟推进的世界时钟、离线照常运行、断电/重启后的状态恢复）
- 前后端实时同步方式（所有旁观者看到同一个世界；推送 vs 轮询）
- 事件引擎：条件与效果字符串规则的解析器、概率、冷却、连锁、去重
- 比赛模拟器、成长系统的实现方式
- 文案生成：模板为主，是否以及如何引入大模型润色
- 数据存储（世界状态、事件历史、干预日志）
- 管理员后台的实现与安全
- 部署方案（面向中国大陆访问，考虑备案与 CDN），以及后续移植微信小程序的路径
- 3D 资源方案（模型来源、性能预算、手机端降级）
- 开发里程碑与工作量估算
