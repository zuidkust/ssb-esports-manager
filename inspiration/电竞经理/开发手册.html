重生之我是SSB职业经理 · 开发手册

v0.1 ｜ 单机网页游戏（纯前端 · 无依赖 · 双击即玩）｜ 本手册给共同开发者：看完即可上手改数值、加卡、加事件
一句话结论：整个项目就是 6 个文件——两个 HTML（游戏 + 引擎调试台）、两个 Node 测试、一个同步脚本、本手册。引擎代码只在主文件里改，同步用脚本，改完必跑测试；所有数据（选手卡/特性/事件/节点）都是 JSON 风格的 JS 变量，找到就能改，不用装任何环境（浏览器即可玩；跑测试需要 Node.js）。

二、开发工作流（最重要的 30 行）

标准改动流程

1. 改 重生之我是SSB职业经理.html（引擎改动在 <script id="engine"> 块内）
2. python 同步引擎.py          ← 同步到调试台（漏了这步，平衡测试测的是旧引擎！）
3. node 游戏测试.js            ← 主测试，全绿才算过
4. node 模拟测试.js            ← 平衡曲线，对照下方"目标带"
5. 打包发队友：整个文件夹压缩即可（存档不在文件夹里，见下）

⚠️ 已知的坑（都踩过）

① 双文件引擎：模拟测试.js 读调试台、游戏测试.js 读主文件。改主文件引擎后不同步就跑模拟测试 = 拿旧数据骗自己。
② 预设/名单顺序：roster 和预设 A/B 数组必须严格对齐 [上单, 打野, 中单, AD, 辅助]（SLOTS 顺序），错位=全错。
③ 账目问题用脚本验证：直播和计分板对不上时先跑对账断言，不要肉眼数（人工数错过 14 vs 15，其实是引擎对的）。
④ 数值平衡的联动：nodeCount、σ、提前GG阈值三者联动（曾因 nodeCount 11→13 导致碾压局暴涨，阈值 4500→5200 才拉回）。改任何一个都要复测全套曲线。
⑤ 存档在浏览器 localStorage（key：dd_esm_season_v2），不在文件夹里——打包给别人 = 别人全新开局。旧存档结构变化时有兜底（teamFive 回退等），但新特性（fit 成长/事件）不回溯。

三、架构速览

重生之我是SSB职业经理.html
├─ <script id="engine">      纯逻辑（Node 可直接编译执行，无 DOM）
│   ├─ 常量：SLOTS / NODE_TYPES（节点类型×属性权重×击杀推塔产出）/ TL_MAIN+TL_OPT（时间轴）
│   ├─        TRAITS（特性表）/ DEFAULT_PLAYERS（SSB 六人 + 调试预设名单）/ PRESETS / DEFAULT_OPTS
│   ├─        EVENTS（31 个赛后随机事件池）/ AI_PLAYER_NAMES / DBD_NAMES
│   ├─ 模拟：buildSeq（时间轴组装）→ simulateMatch（节点循环+逐杀记账+经济+提前GG/膀胱局延长）
│   ├─ 赛季：genLeague（16 队生成）→ createSeason → playSeasonRound → runPlayoffs（BO3）
│   ├─ 成长：applyGrowth（上场选手）/ rollEvent（赛后随机事件）/ addStress
│   └─ 工具：makeRng(种子)  ← 一切随机都吃种子，同种子=同结果（可复现/可对账）
└─ <script>（UI）           Tab 页渲染 / 布阵编辑器 / 直播播放器 / localStorage 读写
调试台的 engine 块与主文件逐字节相同（由同步脚本保证），调试台自己的 UI（滑杆/下拉）在外面，不会被覆盖。

四、数据结构（想加卡/加事件，看这节就够）

选手卡（DEFAULT_PLAYERS 里的格式）

dibi:{id:"dibi",name:"弟必",
  stats:{lane:64,roam:42,fight:74,sense:64,mech:66,pool:62,mental:58},  // 七属性 40-95
  fit:{top:60,jgl:30,mid:88,adc:40,sup:45},     // 位置适性，本命位 85-90
  potential:76,                                  // 成长上限（属性只会逼近不会超过）
  traits:["scalemage"]                           // 特性，见下表
}
段位→属性基准：白银 45-55 / 黄金 55-62 / 白金 62-72 / 翡翠 70-78 / 钻石 78-85。改属性后记得想平衡（SSB 是"你"的队，RGS/Showtime 63-75+star76-80 压着）。英雄池 pool 目前是死属性，留给 BP 禁选系统实装。

赛后随机事件（EVENTS，31 个）

{w:2,name:"沉迷PUBG",                        // w=权重；w≤2 自动标记为大波动彩蛋（实测总触发率 ~7%）
 text:"全员沉迷 PUBG，训练赛迟到……",          // 剧情文案
 fx:function(P,ids,rng){                      // 效果：P=选手表 ids=全队名单 rng=种子随机
   allUp(P,ids,-3);addStress(P,ids,-10);      // 工具：allUp 全属性 / statUp 单属性(带上下限) / addStress
   return "⚠️ 全员全属性 -3 · 压力 -10";}}     // 返回值=赛后卡片展示的效果行
事件在每场比赛后自动触发（常规赛每轮 + 季后赛每局），作用于全队名单（含替补）。当前分布：常规 16（w5-8）+ 剧情 5（w3-4）+ 大波动 10（w1-2）。加事件往数组里 append 即可。

战术指令（TACTICS，五环克制）

强开团 ＞ 保排消耗 ＞ 防守反打 ＞ 速攻节奏 ＞ 运营发育 ＞ 强开团（闭环）
克制方全场节点 ×1.05；各战术另有节点阶段乘数（tacMult 函数）：
  强开团：团战节点+3% / 对线-4% ｜ 保排：对线推塔+10% / 决战-2%
  防守反打：上一节点失利则+4% ｜ 速攻：13'前+16% / 22'后-5% ｜ 运营：20'后+6% / 13'前-7%
调参后克制边实测胜率 70.7%~82.3%（镜像队 300 场）——克制值得选但不是稳赢。AI 反制（aiTactic）：最近 4 轮你同一战术用 ≥2 次，全联盟会针对性选克制你的战术。每队 genLeague 时分配 tactic（RGS=强开团、Showtime=运营、DBD=速攻、城市队随机）。

比赛节点（NODE_TYPES + TL_MAIN/TL_OPT）

每节点 = 类型（属性权重 w + 位置参与度 inv + 击杀产出 kMin-kMax + 推塔 twMin-twMax）× 时间戳。TL_MAIN 固定 11 个（对线3'/小龙5'/…/决战28'，对齐真实资源刷新），TL_OPT 4 个可选（遭遇战9'/抓单12'/18'/遭遇战23'）。nodeCount=13 → 11 固定 + 随机 2 个可选（保证游走节点出场）。时长不固定三机制：时间戳抖动 / 20min 后经济差≥5200 提前 GG / 终局差<2500 追加远古龙团+最后的决战。

五、核心机制速查

机制规则
比赛模拟每节点双方 5 人各算贡献分（属性×权重×适性×对位压制），总分定胜负，胜方按 margin 吃击杀大头；逐杀记账进 kda 账本 → 直播逐杀播报 ↔ 计分板逐人对账可审计
对位压制双通道对位差 pr：判定层 ×0.05（几乎不动胜负平衡）+ 表现层 ×0.45 记入贡献（高属性=高 MVP/评级/击杀，肉眼可见）
经济模型节点胜方 +900~2600g；领先方优势递减、落后方追赶补偿；高地决战 +2800g；大龙 buff 下节点 +8
压力 stress0-100 默认 30；上场每场 +4；>60 每点发挥 -0.12，<22 小幅 +2；≥78 赛前播报。只能靠随机事件浮动（训练类事件 +，放松类 -）
疲劳 fatigue上场每场 +12，替补一轮 -40；>40 每点发挥 -0.09（疲劳 80 的队 vs 疲劳 0 镜像胜率仅 21%）——轮换是必修课，连打 4 场开始明显掉状态
战术指令赛前五选一，克制对手 +5% 全场节点 + 阶段乘数；AI 会反制连用战术；对手风格可侦察（主页/布阵页）
成长每场向潜力逼近（room×0.022×特性倍率）；本命适性 fit 同步向 85 逼近；只有上场五人成长，替补靠事件
阿鸡觉醒队伍 5 连败 或 阿鸡累计 5 场队内垫底 → 属性大涨 + 成长 ×1.8（重生剧本的核心弧线）
六人布阵制SSB roster=6 人，lineup=5 人首发（比赛日前可改，选已在阵中者=互换位置）；AI 队 teamFive=roster
联赛16 队：SSB（你）/ DBD（随机 AI 等真人卡·速攻）/ RGS（EDG青训·强开团）/ Showtime（卫冕冠军·运营）/ 12 城市队（56-68，其中 5 支藏大神 72-78，风格随机）。15 轮 BO1 双循环 + 前 8 名 BO3 季后赛 + 颁奖（MVP/躺赢王/进步最快）
难度校准基准（8 季实测）：摆烂玩家（不轮换+战术从不换）4.6 胜/15，会玩玩家（轮换+侦察克制）9.1 胜/15 —— 操作水平值 4-5 个胜场。如果改数值后这个梯度塌了，说明平衡被打破。

八、待办路线图（按优先级）

  • 局内决策点⭐已拍板要做：直播到关键节点（大龙团/远古龙/高地决战）暂停，玩家 2-3 选一（抢大龙/放龙换塔/强开团），直接解决"点开始前结果已注定"——建立在现有节点系统上
  • BP 禁选系统⭐已拍板要做：英雄池 pool 属性在此实装（池浅被 ban 命根英雄掉属性），需先建英雄数据表（100+ 英雄×位置×克制）——策略天花板最高
  • DBD 真人卡：DD 会继续提供群友资料（格式：主位置/段位/风格印象/名场面/潜力直觉），替换 DBD 的随机 AI
  • S2 全国赛：职业选手 AI 入场（注意：厂长/Ning/宝蓝/圣枪哥等名字 S1 已用作城市赛选手，S2 要换 LPL 级阵容或圆设定）
  • 转会市场 / 手动训练分配 / 存档导出导入（存档在 localStorage，想给朋友发进度需要做这个功能）

协作约定

  • 游戏和攻略都是自包含单文件 HTML：不引外部资源、不拆文件、双击就能玩
  • 引擎只改主文件；改完 python 同步引擎.py + 两个测试全绿，才算一次合格提交
  • 文案风格：玩梗但不虚报数字（直播里的数字必须和计分板对得上）；数值严谨和喜剧效果并重
  • 涉及真实选手/战队名：仅致敬城市英雄争霸赛等公开历史，自用不盈利

九、新接手者的 10 分钟上手路线

  1. 双击 重生之我是SSB职业经理.html 玩一整个赛季（约 15 分钟）：布阵→直播→赛后事件→季后赛
  2. 双击 引擎调试台.html：跑一次 1000 场批量，看胜率曲线长什么样
  3. 装 Node.js，在文件夹里跑 node 游戏测试.js 和 node 模拟测试.js，确认全绿
  4. 打开主文件搜索 EVENTS，随便给一个事件改个文案/数值 → 重跑测试感受工作流
  5. 读完本手册第四、六节，就可以动手改卡/加事件了
