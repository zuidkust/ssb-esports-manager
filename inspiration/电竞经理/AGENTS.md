# AGENTS.md — 重生之我是SSB职业经理（电竞经营游戏）

单机网页游戏：纯前端、无依赖、无构建步骤、非 git 仓库，共 6 个文件（全部中文命名）。完整文档在 `开发手册.html`——改选手卡/数值/事件前先读其第四、六节。

## 文件分工
- `重生之我是SSB职业经理.html` — 游戏本体 + **权威引擎源**。两个 script 块：`<script id="engine">`（纯逻辑、无 DOM，Node 可直接编译执行）+ 无名 script（UI/存档/Tab 渲染）。
- `引擎调试台.html` — 调参工具（滑杆/批量模拟）。其 engine 块是主文件的**逐字节镜像**（同步脚本保证），永远不要直接改它的 engine 块。
- `游戏测试.js` — 全量回归（**读主文件**）：语法检查、KDA 账目对账（ΣA.k≡ΣB.d）、直播↔计分板逐人对账、真实感指标断言、赛季全流程。
- `模拟测试.js` — 平衡校准（**读调试台**）：5 组预设 ×1000 场胜率曲线、阿鸡觉醒对比、计分板/赛季冒烟。
- `同步引擎.py` — 把主文件 engine 块整块替换进调试台（Python 3，正则块替换）。

## 必走工作流（改引擎或数值后）
```bash
python 同步引擎.py   # 先同步！漏了这步，模拟测试测的是旧引擎
node 游戏测试.js      # 主回归，全绿才算过
node 模拟测试.js      # 平衡曲线，对照手册第六节"目标带"
```
引擎只在主文件 `<script id="engine">` 块内改；只动 UI/文案时跑 `node 游戏测试.js` 即可。

## 关键坑（都实际踩过）
- **双文件引擎**：游戏测试读主文件、模拟测试读调试台。改完主文件引擎必须先 `python 同步引擎.py` 再跑模拟测试。
- **roster/预设数组顺序**：必须严格对齐 SLOTS 顺序 `[上单, 打野, 中单, AD, 辅助]`，错一位全错。
- **账目/对不上问题**：先用测试脚本里的对账断言验证，不要肉眼数（人工数错过）。
- **参数联动**：nodeCount、σ(sigma)、提前 GG 阈值(5200) 三者是一起调好的，改任何一个都要复测全套平衡曲线。
- **一切随机吃种子**（`makeRng`），同种子=同结果；测试的可复现性依赖这一点，不要引入无种子随机。
- **存档在浏览器 localStorage**（key `dd_esm_season_v2`），不在文件夹里；结构变更有兜底但新特性不回溯。

## 约定
- 游戏保持**自包含单文件 HTML**：不引外部资源、不拆文件、双击即玩。
- 文件名、注释、文档、游戏文案均用中文。
- 文案风格：玩梗但不虚报数字——直播里的数字必须和计分板对得上。
- 所有数据（选手卡 `DEFAULT_PLAYERS`、特性 `TRAITS`、赛后事件 `EVENTS`、节点 `NODE_TYPES`+时间轴）都是 JSON 风格的 JS 变量，找到即改；加事件往 `EVENTS` 数组 append 即可（w≤2 自动算大波动彩蛋）。
- 英雄池 `pool` 目前是死属性，预留给 BP 禁选系统实装。

## 平衡验收基准（改数值不能破坏）
镜像对局胜率 ~51%；难度梯度：摆烂玩家 4-5 胜/15 轮 vs 会玩玩家（轮换+战术克制）9 胜/15 轮。真实感指标（场均击杀 20-27、推塔 ~12、时长 ~30:50、ADC 击杀显著高于辅助）由 `游戏测试.js` 断言，目标带详见手册第六节。
